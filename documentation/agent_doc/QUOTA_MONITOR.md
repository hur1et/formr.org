# Read-only provider quota monitor

Implemented/tested 2026-10-15, documented 2026-10-16. Development feature; no deployment.

## User contract

The researcher opens Quotas in the run menu and chooses **Create provider link**
under **Provider statistics**. The resulting URL is displayed for copying, with an
Open provider statistics link and a **Revoke provider link** button. No automatic
sharing or messages to providers occur. Anyone holding the link can read the aggregates
without a formr account. Revoke disables that key; creating a new link gives a new key.
Repeated create requests preserve the current link. Viewing the admin page creates none.

Use the existing study URL with the `quotas` action, generated by `run_url`:

- Folder mode: `http://127.0.0.1:8097/Quoten_Demo/quotas/?key=<key>`.
- Study subdomain mode: `https://study.example.org/quotas/?key=<key>`.

No additional subdomain, DNS record or certificate is needed. The page is plain HTML,
rendered from current database values on each reload; no polling or generated-file job.
All quota tables show Code, Quota group, Limit, Count and Fulfillment. At 100% and above
the percentage cell is green, with actual overfill visible. Limit zero shows an uncolored
em dash. A timestamp states when this response was generated, in UTC.

Only field aggregates are published, regardless of a supplied `cohort` parameter.
Completed participants counts unique completion records, separately from group corrections.
No participant codes, provider IDs, answers, configuration payloads or correction history
are returned. Draft groups can be viewed before activation with zero counts; an empty
run shows a short no-groups message. There are no editing controls or scripts.

## Implementation and boundaries

`QuotaMonitor` manages owner-only link creation/revocation under a run-row lock.
Patch 064 adds one random 256-bit key per run, with a unique database constraint and
creation timestamp. The key is stored server-side so the owner can copy the existing
URL on later visits. It grants aggregate viewing only; treat URLs as access links and
avoid logging or exporting them. Existing web-server access logs may contain query
strings; review their access/retention before deployment. Run import/export must not
copy keys; the portable implementation excludes them (QUOTA_STRUCTURE.md).

Reading validates the key against that run and calls the same `QuotaOverview` field
reader as the researcher page. Its output is reduced to name, completed total and group
display rows. The provider cannot select a cohort or pass mutations through this API.
The `RunController` private action runs before participant login/execution; no run or
unit session is created. Existing folder/subdomain routing is reused without changes.
Administration uses the native `quota_share` private-action naming convention.

GET and HEAD are supported; other methods return 405 and `Allow: GET, HEAD` before
reading monitor data. Missing, incorrect, cross-run and revoked keys return 404.
Technical read failures return 503 rather than presenting zero counts as success.
Success and failure responses disable HTTP storage. Referrer policy, indexing headers
and a restrictive CSP prevent external assets/scripts, form submissions and framing.
The standalone template loads no study-authored scripts or third-party resources.
The existing service worker caches asset URLs only, not this route.

Apply development patches 060-064 before use, including the researcher Quotas page.
Coordinate patch numbering with upstream before release. This feature adds no external
service, dependency or background worker. It does not change provider callback settings.
